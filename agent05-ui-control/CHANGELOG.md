# Changelog

All notable changes to XtractManager (agent05-ui-control) are documented here.

## [Unreleased]
- **Запуск refiner «урок» идёт по словам под сомнением:** `prompt: lesson` в `POST /api/jobs/{id}/refine` теперь просит у agent06 запуск `candidates_only` вместо прохода по всем строкам с проверкой правок. agent06 сам находит слова, которые могут быть испанскими, но записаны кириллицей или буквами двух алфавитов, спрашивает модель только о языке каждого и пишет написание, которое уже есть в расшифровке; строк модель не возвращает. На 33 диалогах уроков: 54 слова переписано (43 верно, 2 во вред, 9 спорных) за 60 запросов против 15 правок (13 верных) за примерно 2 840 запросов при прежнем запуске. UI: пункт переключателя называется «Урок (только слова под сомнением)», пояснение под ним переписано; в таблице хода refine над строками запроса показаны слова, о которых спрошена модель (поле `asked` события `refine_progress`, `askedWords` в `refine-batches`). `saved` работает как раньше. См. README, «Запуск refiner», и README agent06, «Words in doubt».
- **Фаза задания с диска следует за refine:** обновление задания, которое сервис не создавал в этом запуске процесса (после перезапуска agent05 это все задания), раньше молча терялось — во время refine задание оставалось в `awaiting_refiner`, кнопка Run Refiner не гасла, второй `POST /api/jobs/{id}/refine` не получал отказа и запускал второй платный прогон, после прогона задание не становилось `completed`. Теперь при первом обновлении такое задание берётся в память (`IAdoptingJobStore`, фаза и статус — из `xtract_ui_state.json`, чанки по-прежнему читаются из папки): на время прогона фаза `refiner`, второй запуск получает 409, после прогона — `completed`; `skip` тоже оставляет задание `completed`. Фаза `refiner`, оставшаяся в `xtract_ui_state.json` после остановки сервиса посреди прогона, читается как `awaiting_refiner` / `failed` — задание больше не застревает и запускается заново.
- **Выбор prompt при запуске refiner:** `POST /api/jobs/{id}/refine` принимает поле **`prompt`**: `lesson` — встроенный prompt agent06 для урока со своим размером блока (5 строк, 2 строки контекста), моделью по умолчанию и проверкой правок (`respelling_only`: из правок модели остаётся только испанское слово, записанное кириллицей и переписанное латиницей); `saved` или без поля — настройки вкладки Refiner, как раньше; другое значение — 400. Снепшот задания получил поле **`lesson`** (в папке есть `track_source.json` или `dialogue.json`). UI: в панели Refiner переключатель «Prompt запуска» с пояснением под ним; для задания из уроков и для диалога первым стоит prompt урока, для обычной загрузки — сохранённые настройки. Раньше клик Run Refiner всегда брал сохранённые настройки, и prompt, написанный для другого материала, портил транскрипт урока. См. README, «Запуск refiner».
- **Доли речи в списке уроков:** запуск дорожки в `GET /api/sessions` получил поле **`share`** (та же форма, что `total` в `GET /api/jobs/{id}/language-share`; `null`, пока нет ответов чанков). UI показывает рядом с запуском «es 74 % · ru 18 %», полная строка — в подсказке. Доли хранит `JobLanguageShareCache` в памяти процесса: считаются один раз и пересчитываются, когда меняется число, размер или время записи файлов с ответами; первый список после запуска считает все задания параллельно. Тесты: `JobLanguageShareCacheTests`, `SessionsControllerTests`, `languageShare.spec.ts`.
- **Паузы и перебивания в диалоге:** ответ `GET /api/jobs/{id}/language-share` у задания-диалога получил блок **`conversation`**: сколько секунд говорят одновременно и сколько молчат, сколько раз сменился говорящий, и по каждому участнику — перебивания (строка начата поверх чужой речи и двое затем говорят вместе не меньше 1 с), поддакивания (до 2 слов и 1,5 с поверх чужой речи), обычное ожидание перед ответом и долгие паузы (от 3 с) перед ответом и в своей речи. Строки дорожек ставятся на шкалу записи по `timeline/chunks.json` и `timeline/speech_map.json` (`JobTimedLinesReader`); где это невозможно (задания старше этих файлов, чанк склеен из частей), блок равен `null`, доли считаются как раньше. Пауза короче секунды внутри строки считается речью, так что «говорят одновременно» — оценка сверху. UI показывает строку «Разговор …» и по строке на участника под долями диалога. Заодно доли речи больше не считают сегменты из защитной зоны чанка (`emit_guard_sec`) — число строк диалога теперь равно числу строк его transcript. Тесты: `ConversationStatsTests`, `JobTimedLinesReaderTests`, `languageShare.spec.ts`.
- **Доли речи по дорожке:** новый **`GET /api/jobs/{id}/language-share`** считает по ответам чанков в папке задания (`chunks_json/*.json`, у разделённого и склеенного чанка — по ответам частей), сколько секунд речи идёт по-испански, по-русски и смешанными строками: слово латиницей — испанское, с кириллической буквой — русское; строка испанская от 70 % латинских слов, русская до 30 %. У задания-диалога ответ несёт запись на каждую дорожку и сумму, так что видно и долю речи каждого участника. UI показывает это строкой под настройками запуска («Речь 31,5 мин: испанский 69 % · русский 26 % · смешанные строки 5 %»). Папка задания только читается; паузы и перебивания не считаются. Тесты: `JobLanguageShareReaderTests`, `languageShare.spec.ts`.
- **Дорожка участника по умолчанию идёт моделью `gpt-transcribe`:** `POST /api/sessions/runs` для дорожки участника, у которой в `settings` не названа модель, дописывает в `job_settings.json` модель из нового ключа **`Recordings:ParticipantTrackModel`** (по умолчанию `gpt-transcribe`; пустое значение выключает правило). Названная модель остаётся; общая дорожка и обычная загрузка идут моделью общего config agent04, как раньше. `GET /api/sessions` получил поля **`participantTrackModel`** и **`participantTrackEstimateUsdPerMinute`** (ключ `Recordings:ParticipantTrackEstimateUsdPerMinute`, по умолчанию 0,01). UI: оценка на кнопке **Расшифровать** и в подтверждении считается по модели, которой задание пойдёт (40 минут дорожки участника — «≤ $0.41» вместо «≤ $0.69»; при выборе другой модели в форме оценка пересчитывается); в подтверждении сказано, какой моделью пойдёт дорожка, пустой пункт списка моделей называет её. Тесты: `SessionsControllerTests`, `JobSettingsTests`, `lessons.spec.ts`.
- **UI / настройки задания — модель `gpt-transcribe`:** в списке моделей формы настроек задания (загрузка файла, запуск дорожки из уроков) появилась `gpt-transcribe`; подсказка поясняет, что она пишет испанское по-испански, русское по-русски и не различает говорящих — для дорожки одного участника. API не менялся: `settings.model` уже принимал любой идентификатор модели; как agent04 транскрибирует таким заданием — в `agent04/README.md` («Plain-text model»).
- **UI / выбор задания:** клик по заданию, которое уже открыто (его строка в боковом списке или его запуск в списке уроков), больше не оставляет пустую карточку — раньше снимок задания сбрасывался, а перечитывался только при смене id (`useJob.setJobId`). Задание, выбранное в боковом списке, открывается на шаге Transcriber, если была открыта форма загрузки или она запомнена как последний шаг этого задания, — раньше по клику показывалась форма загрузки.
- **Настройки запуска в карточке задания и в уроках:** снепшот задания (`GET /api/jobs/{id}`, SSE) получил поле **`runSettings`**, запуск дорожки в `GET /api/sessions` — поле **`settings`**: `{ source, model, silenceCompress, silenceKeepSec, fromJobSettings }`. Читается из папки задания при каждом запросе (`JobRunSettingsReader`), папка только читается. Источники по порядку: `run_settings.json` — запись agent04 при приёме задания, точная (`source: "run"`); задание старше этой записи — по тому, что оставил запуск (`timeline/speech_map.json` или `converted_wav/*.silence_report.json` → сжатие было, пауза такая-то; только `*.silence_detect.json` → сжатия не было; модель известна, только если оператор задал её в `job_settings.json`) — `source: "artifacts"`; задание ещё не шло — то, что задал оператор (`source: "job_settings"`). Чего папка не говорит, приходит как `null`: из сегодняшнего общего config ничего не подставляется. UI: строка «Настройки запуска: …» над содержимым шага задания, короткая подпись у запусков в списке уроков и в выборе запуска для диалога. Тесты: **`JobRunSettingsReaderTests`**, **`SessionsControllerTests`**, UI **`runSettings.spec.ts`**.
- **Уроки из папки записей:** новый ключ **`Recordings:RootPath`** и **`GET /api/sessions`** — папка записей читается в уроки → периоды Zoom → дорожки (общая и по участникам); видны периоды, которые Zoom не сконвертировал, и папки периодов, оставшиеся в корне. У каждой дорожки — задания, которые её транскрибировали (по `track_source.json`, по имени и размеру файла, по размеру и первым 64 КБ), у периода — собранные из них диалоги. **`POST /api/sessions/runs`** копирует файл дорожки в новую папку задания, пишет `track_source.json` (и `job_settings.json`, если заданы настройки) и ставит задание в очередь; папка записей только читается. UI: кнопка **Уроки** в шапке — список уроков, переход к заданию, **Расшифровать** с верхней оценкой цены и подтверждением, **Собрать диалог** из дорожек участников. Новое: **`RecordingsScanner`**, **`RecordingsCatalog`**, **`TrackRunsIndex`**, **`TrackSourceFile`**, **`SessionsController`**, `UI/src/components/LessonsPanel.tsx`, `UI/src/utils/lessons.ts`; блок настроек задания вынесен в **`JobSettingsFields`**. Тесты: **`RecordingsScannerTests`**, **`SessionsControllerTests`**, `lessons.spec.ts`.

- **Настройки одного задания при загрузке:** `POST /api/jobs` принимает поле формы **`settings`** (JSON: `silence_compress_enabled`, `silence_keep_sec`, `model`), проверяет его и пишет `job_settings.json` в папку задания до постановки в очередь; agent04 кладёт файл поверх общего config, сам `default.json` не меняется. Неверные настройки — 400, задание не создаётся. UI: блок «Настройки этого задания» в карточке загрузки (сжатие тишины, оставляемая пауза, модель; пустое поле — «как в общем config»). Новое: **`JobSettingsDocument`**, `UI/src/utils/jobSettings.ts`. Тесты: **`JobSettingsTests`**, `jobSettings.spec.ts`.
- **Диалог из дорожек — чанк, заменённый частями:** чанк без отметок времени, который оператор разделил и транскрибировал по частям, больше не даёт пометку «(без времени)» — раньше её получала первая строка частей, если она стояла на том же времени, что и старый блок. Часть такого чанка, вернувшаяся без отметок времени, даёт строку в `warnings`.
- **Диалог из дорожек — предупреждение о сжатой шкале:** если дорожка транскрибирована со сжатием тишины, а таблицы `timeline/speech_map.json` у её задания нет (задание старше карты речи Agent04), `POST /api/jobs/dialogue` добавляет в `warnings` строку о том, что времена этой дорожки не на шкале записи.
- **Диалог из дорожек участников:** **`POST /api/jobs/dialogue`** собирает один transcript из заданий-дорожек (по одному на участника Zoom): метки `speaker_N` заменяются именем участника, строки идут в порядке времени, без склейки. Диалог живёт отдельным заданием (`transcript_dialogue_<время>.md` + `dialogue.json`, фаза `awaiting_refiner`, тег `dialogue`); задания дорожек только читаются, модель не вызывается, refiner не запускается. Строка чанка без отметок времени получает метку `<имя> (без времени)`. **`POST /api/jobs/{id}/dialogue/rebuild`** пишет новое слияние рядом с прежними. Имя архивного задания-диалога в списке — `title` из `dialogue.json`. Тесты: **`TrackDialogueMergerTests`**, **`DialogueBuilderTests`**.
- **UI / список заданий:** длинное имя задания больше не выталкивает кнопку «×» за край панели — кнопке строки добавлен `min-width: 0`, имя сокращается многоточием.
- **Chunk panel / job switching:** `ChunkControlPanel` всегда на вкладке Transcriber: режим **live** (транскрипция running) с действиями по чанкам и **view-only** для архива/завершённых (данные с диска, без живого Agent04). **GET /api/jobs/{id}** и архивные снимки обогащаются с диска: **`transcription_work_state.json`** → `chunks` / `chunkVirtualModel`; при отсутствии — эвристика по **`chunks/*.wav|m4a`**; опционально **`xtract_ui_state.json`** (фаза/статус/`agent04JobId`) для подсветки шагов у архива — файл пишет пайплайн при обновлениях снимка. **`useJob`:** в `localStorage` сохраняется шаг **`xtract-manager-active-step-{jobId}`** при смене шага и при старте нового job. **Консольные логи** API и Agent04: метка времени **UTC** (`SimpleConsole` + `UseUtcTimestamp`). Тесты: **`JobSnapshotDiskEnricherTests`**.
- **Proto Agent04 (sync):** `ChunkVirtualModelEntry` — поля **`is_sub_chunk`**, **`parent_chunk_index`**, **`sub_chunk_index`**; RPC **`EnqueueTranscriptionWork`** (очередь индексов через `pending_chunks.json` на стороне Agent04). Клиентский `transcription.proto` выровнен с `agent04/Proto/transcription.proto`.
- **API / SSE JSON:** в **`ApiJson.CamelCase`** задан **`Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping`**, чтобы снимки заданий и стрим содержали читаемый Unicode (без `\uXXXX` для не-ASCII), согласованно с agent04/agent01.
- **План HttpClient + Split (Agent04 / Xtract):** в снимок задания добавлено **`transcriptionError`** (сообщение Agent04 при `Failed`/`Cancelled` и ошибках submit); в **`chunkVirtualModel`** — **`errorMessage`**. API: **`ChunkActionRequest.splitParts`** (для `action: split` обязательно **≥ 2**), gRPC **`split_parts`**. Agent04: операторский **Split** в `split_chunks/`, фаза при падении не залипает в «Chunking», сводка батча и логи OpenAI (короткое замыкание при отмене токена, `HttpAttemptId`, таймаут vs отмена). UI: баннер ошибки на Transcriber/Result, **`ChunkControlPanel`** при **`failed`** + VM (только чтение), колонка детали, **Split** с запросом числа частей; на SSE **`done`** при **`failed`** не переключает шаг на Result автоматически; warn в пайплайне — **`ProcessedChunks`/`TotalChunks`**.
- **SSE snapshot / UI:** снимки в Event Stream сериализовались через `JsonSerializer.Serialize` без политики имён → **PascalCase** (`Status`, `Chunks`, …), тогда как `GET /api/jobs/{id}` отдаёт **camelCase**. После первого SSE `setJob` затирал состояние «ломанным» объектом: `ChunkControlPanel` не видел `phase`/`status`/`chunks` и не рендерился, пока не помогал повторный HTTP-запрос. Исправлено: общие **`ApiJson.CamelCase`** (`JsonSerializerDefaults.Web`) для начального кадра stream и всех `snapshot`/`status` из `TranscriptionRefinerPipeline`.
- **Файлы проекта после сплита:** при каждом SSE **`snapshot`** увеличивается **`jobSnapshotRevision`** в `useJob`; на шаге Transcriber он передаётся в **`ProjectFilesPanel`** как **`filesRefreshKey`**, чтобы **`GET .../files`** выполнялся снова без смены вкладки. Документ **`docs/JOB_FILES_SCANNER_AND_AGENTS.md`**: раздел про SSE vs файлы vs RENTGEN.
- **`chunkVirtualModel` в снимке:** при обновлении из Agent04 пустой список VM больше **не затирает** ранее полученные строки (`TranscriptionRefinerPipeline`). Пока VM пуста, а **`chunks.total` > 0**, **`ChunkControlPanel`** показывает таблицу-скелет из **`total`** строк со статусом Pending.
- **Чанки в UI:** таблица по данным виртуальной модели Agent04 (`chunkVirtualModel`: индекс, прошедшее время по ISO `startedAt`/`completedAt`, статус, кнопка «×» для отмены активного чанка). Проксирование поля из gRPC `JobStatusUpdate.chunk_virtual_model`.
- **Корень артефактов = папка задания:** chunk-actions в gRPC передают **`job_directory_relative`** (= id задания Xtract); refine — **`job_directory_relative`** + **`output_file_path`** `transcript_fixed.md`, когда выход в координатах папки job. При старте API: если заданы и **`Jobs:WorkspacePath`**, и **`Agent06:WorkspaceRoot`**, сравниваются нормализованные полные пути — при расхождении **Warning**; при **`Xtract:RequireAgent06WorkspaceMatchesJobs` = true** — **fail fast** (`WorkspaceParityChecker`). Proto **`refine.proto`**: поле **`job_directory_relative`** (15). Юнит-тесты: **`WorkspaceParityCheckerTests`**.
- **Логи транскрипции (консоль):** перед вызовом Agent04 и при ошибках — `TranscriptionRefinerPipeline` + `TranscriptionGrpcClient` пишут в лог пути (`ConfigPath`, `workspaceRoot`, файл на диске, относительный `inputFilePath`), при `RpcException` — `StatusCode` и `Detail`; при `Failed` из стрима статуса — `ErrorMessage` и фаза. Уровень по умолчанию в `appsettings`: для категорий `XtractManager.Features.Jobs.Infrastructure` при необходимости выставить `Information` / `Warning`.
- **Загрузка аудио:** файл в каталоге задания сохраняется под **санитизированным оригинальным именем** (как в multipart `FileName`), а не как `audio.<ext>`. Недопустимые символы заменяются на `_`, путь в имени отбрасывается (`Path.GetFileName`), зарезервированные имена Windows получают префикс `_`, длина ограничена 255 символами. Пайплайн транскрипции ищет тот же путь; для старых папок с `audio.*` остаётся **fallback**.
- **DELETE /api/jobs/{id}:** для заданий, видимых только с диска (архив, без записи в in-memory store), раньше возвращался **404**; теперь при наличии каталога задания под `Jobs:WorkspacePath` он **удаляется рекурсивно** (с проверкой, что путь остаётся внутри workspace), ответ **204** как для обычного удаления. Для заданий в памяти по-прежнему удаляется запись и **также** снимается папка на диске, если она есть.
- **Список заданий:** для каталогов на диске без записи в in-memory store (архив / другой запуск) в `GET /api/jobs` подставлялось **`OriginalFilename` = «—»**; теперь то же определение имени, что и в `Get` — **первый аудиофайл в папке задания**, иначе **id задания**.
- **UI:** переключатель **светлой и тёмной** темы (кнопка в topbar, CSS variables в `index.css`, `ThemeProvider` + `localStorage` `xtract-theme`, ранний скрипт в `index.html` против мигания).
- **План §6 + критерий готовности:** документы **`docs/JOB_FILES_SCANNER_AND_AGENTS.md`** (таблицы сканера vs Agent04/06) и **`docs/PARITY_MINIMUM_READINESS.md`** (чеклист минимального паритета); в README — краткая сводка и ссылки.
