# Agent04 — Transcription service (.NET)

.NET reimplementation of the agent01 transcription pipeline: OpenAI transcription (diarization), ffmpeg chunking, cache by fingerprint, merge, Markdown/JSON output. Clean Architecture, vertical slice `Features/Transcription`. **Web service only** (no CLI); **public API — gRPC only** (HTTP REST/OpenAPI removed; orchestrators such as agent05 use gRPC).

## Requirements

- .NET 9
- ffmpeg / ffprobe on PATH (or set in config)
- OpenAI API key (e.g. `env:OPENAI_API_KEY` in config)

## Configuration

- **Workspace root (required):** set `WorkspaceRoot` or `workspace_root` in `appsettings.json` or environment to an **absolute path** of the workspace directory. The app checks that this directory exists at startup and exits if it does not. All paths in gRPC requests are relative to this root.
- **Job config:** same contract as agent01. Example: `Agent04/config/default.json`. Keys include `file`/`files`, `openai_api_key` (e.g. `env:OPENAI_API_KEY`), `model`, `md_output_path`, `raw_json_output_path`, `cache_dir`, `split_workdir`, etc. Paths in job config are relative to the workspace root.

## Running

Start the web host:

```bash
cd Agent04
dotnet run
```

Ensure `appsettings.json` (or environment) contains a valid `WorkspaceRoot` path before starting.

- **Console logging:** timestamps are **UTC** (see `Program.cs`, `SimpleConsole` + `UseUtcTimestamp`).

- **Порт (профили http/https):** **http://localhost:5032** — только **HTTP/2 (h2c)** для gRPC. На Windows без TLS для gRPC нужен отдельный endpoint с h2c (см. `Program.cs` → `ConfigureKestrel`).

## gRPC API

Paths in requests are relative to the instance `workspace_root` (from config):

- **TranscriptionService.SubmitJob** — submit job (`config_path`, `input_file_path`, optional `tags`, optional `callback_url`).
- **TranscriptionService.GetJobStatus** — status by `job_id`.
- **TranscriptionService.StreamJobStatus** — server stream of status updates until terminal state.
- **TranscriptionService.QueryJobs** — list/filter jobs (semantic key, status, time range, limit/offset).
- **TranscriptionService.ChunkCommand** — операторские действия по чанку (`action`, `chunk_index`, опционально **`split_parts`** для **Split**); **Cancel** помечает чанк к пропуску (per-job cancel dir) и отменяет in-flight HTTP через токен; **Skip / Retranscribe** могут отвечать `not_implemented`. **Split** при `split_parts >= 2` режет выбранный файл чанка (ffmpeg) в `split_chunks/chunk_{N}/sub_chunks/` через **`IProjectArtifactService`**. **DeleteSubChunk** (`CHUNK_COMMAND_ACTION_DELETE_SUB_CHUNK`, `sub_chunk_index`) удаляет артефакты одного субчанка (audio, result json, merged, cancel flag, строка work state); при **Running** в Rentgen для узла субчанка — `FailedPrecondition`. Метаданные команды пишутся в виртуальную модель узлов (RENTGEN), если зарегистрирован `INodeModel`. **LookAgain** (`CHUNK_COMMAND_ACTION_LOOK_AGAIN`, `chunk_index` ≥ 0 или −1 — все чанки; только завершённое задание модели `gpt-transcribe`, платно) переспрашивает с соседним звуком (`speech_pieces_context_sec`) строки сохранённых ответов, которые находят сегодняшние сомнения и которые при распознавании не переспрашивались, заменяет строку по тем же правилам, пишет json чанка, его md (кроме исправленного оператором) и запись кеша и собирает общий транскрипт в новый `transcript_<stamp>.md`; ответ — `look_again_ok: chunks …, changed …, lines asked …, taken …, audio …s, md kept …, transcript …`. Повторный вызов ничего не спрашивает.
- **TranscriptionService.EnqueueTranscriptionWork** — записывает `pending_chunks.json` (индексы чанков для следующего прогона пайплайна) рядом с артефактами job; при следующем **SubmitJob** список пересекается с доступными индексами.
- **TranscriptionService.GetChunkArtifactGroups** — только чтение: группы файлов чанков / split (как Stats в agent05), без строк VM; `total_chunks` в запросе можно взять из снимка job или 0 (тогда из `transcription_work_state.json` / эвристика по файлам).

Proto: `Agent04/Proto/transcription.proto`.

Контракт персистентного слоя артефактов job на диске: **`docs/PROJECT_ARTIFACT_SERVICE.md`** (`IProjectArtifactService` / `ProjectArtifactService`).

> **RENTGEN / узлы:** ранее дерево узлов отдавалось по HTTP (`GET .../nodes`). Внешнего HTTP больше нет; для списка заданий используйте **QueryJobs**. При необходимости дерева узлов — расширение `.proto` или отдельный read-сервис (см. `docs/RENTGEN_IMPLEMENTATION.md`). Аудит чанков, под-чанков и связи с RENTGEN — **`docs/CHUNKS_AND_RENTGEN.md`**.

## Parallel transcription & HTTP logs

- **`parallel_transcription_workers`** in the job config caps how many chunks are transcribed **at the same time** (clamped to **1–64**; default in repo sample **6**). Values **> 32** log a warning (higher risk of **429** / rate limits). The scheduler uses a **sliding window** (`Parallel.ForEachAsync`): when one chunk finishes, the next index in the queue can start without waiting for the rest of a former “batch”. Manifest/cache writes stay serialized per job so the cache file is not corrupted under concurrency.
- **Chunk failures:** a failure on one chunk does **not** abort other chunks (unless the error is classified as global: **401/403**, **insufficient_quota**, etc. — then the whole job stops). Markdown/JSON merge order is preserved by index.
- **The account is refused (no credits, the key):** `TranscriptionWorkflowAbort.RefusalReason` reads the server's word for it (`insufficient_quota`, `billing_not_active`, `invalid_api_key`, `account_deactivated`, else 401/403). The client then throws `TranscriptionAccountRefusedException` after **one** request — no retry, no other parameter set, no other model (a bare 403 still tries the other models first). `SpeechPiecesTranscription` neither retries such a request nor counts it as a piece without an answer: the chunk fails, and its requests not yet sent are not sent. The job ends as failed with the reason as its error (for example "OpenAI refused the request: the account has no credits left (insufficient_quota). Add credits to the account and start the job again."), the chunk that met the refusal is `Failed` in `transcription_work_state.json`, and no chunk without text is stored as completed. Before, a `gpt-transcribe` job went on asking every piece of every chunk three times and ended as "N chunk(s) failed" with hollow chunks marked completed; a diarize job stopped, but its error read "A task was canceled."
- **Disk state:** `transcription_work_state.json` in the job artifact root is updated as chunks progress; if missing, a legacy bootstrap may create it from `chunks/` + `chunks_json/` (see `docs/LEGACY_WORK_STATE_RECOVERY.md`). **`pending_chunks.json`** can be written by **`EnqueueTranscriptionWork`** gRPC and is consumed on the next pipeline run (intersected with any explicit chunk filter).
- **Chunk timeline:** `timeline/chunks.json` in the job artifact root is written right after chunking: for every main chunk its file name, `offset_sec` (where the chunk starts in the audio that was split) and `emit_guard_sec` (leading overlap with the previous chunk). `chunks_json/` keeps chunk-local times, so **rebuild_combined** and **retranscribe** read this file to put a regenerated `chunks_md/*.md` back on the recording's timeline. Jobs transcribed before the file existed get the same numbers derived from the first chunk's duration and `chunk_overlap_sec`.
- **Retranscribe and the chunk's md:** **retranscribe** of a main chunk writes the chunk's `chunks_md/*.md` anew together with its `chunks_json/*.json` — when nobody edited the md: the file is absent, or it is exactly what the previous answer of the chunk renders to (line endings aside). An md that differs from that (edited by the operator, or with no previous answer to compare with) is left as it is and the log says so; the new answer is then in `chunks_json` only. **rebuild_combined** still never overwrites an existing chunk md; run after a retranscribe, it puts the refreshed md into a new combined transcript.
- **Job settings:** `job_settings.json` in the job folder (written by the orchestrator at upload) holds the settings of that one job; they go on top of the shared config, which stays as it is for every other job. Shape: `{ "schema_version": 1, "transcription": { "silence_keep_sec": 1.0 } }`. Accepted keys: `silence_compress_enabled` (true/false), `silence_keep_sec` (0.05–5), `model` (a model id), `chunk_overlap_sec` (0–30: how many seconds neighbouring chunks share; the shared config keeps 1 — agent05 runs the diarize model with 12 on a mixed recording that is transcribed only for its speakers, and ties the speakers the model names anew in every chunk by the words both chunks heard). **SubmitJob** and the chunk commands that read the config (**TranscribeSub**, **retranscribe**, **rebuild_combined**, **rebuild_split_merged**) apply the file; a file that cannot be read as settings (not JSON, an unknown key, a value out of range) rejects the request — a job never runs silently with other settings than asked. A job that names another `model` than the shared config also gets that model's answer format: the diarize model `diarized_json` + `chunking_strategy: auto`, `whisper-1` `verbose_json` (lines with times, no speakers), other models plain `json` (text without times). The model of a call now comes from the job config (`model`); before, the client always used the model of the service.
- **Run settings record:** when a job is accepted (`SubmitJob`), `run_settings.json` is written into the job folder — the shared config with the job's own settings on top, i.e. what the pipeline is started with: `{ "schema_version": 1, "written_at": "2026-11-14T00:10:00Z", "model": "gpt-4o-transcribe-diarize", "silence_compress_enabled": true, "silence_keep_sec": 1.0, "from_job_settings": ["silence_keep_sec"] }`. `from_job_settings` lists the keys that came from `job_settings.json`; `silence_keep_sec` matters only when compression is on. It is a record for readers (the orchestrator shows it in the job view): nothing reads it back, a write failure is only logged, chunk commands do not rewrite it.
- **Kept pause:** the silence left in place of a pause is `silence_keep_sec`, but never more than the pause itself — with `silence_keep_sec: 1.0` a pause of 0.5 s stays 0.5 s instead of growing to 1 s. The shared config keeps **1.0 s** (`silence_keep_sec` in `config/default.json`; it was 0.2 s until 2026-11-13): on a one-voice track the model merged phrases separated by long pauses when it heard only 0.2 s between them and put the line 6–20 s early; with 1.0 s the checked phrases stand within 0.5 s of an uncompressed run, at about 20 % more tokens. A job can still take another value through its job settings.
- **Chunk the server refuses:** when the request with time marks gets HTTP 5xx three times, the chunk is cut into `server_error_split_parts` parts (shared config: **4**; 0 or 1 switches it off; a part is not made shorter than 10 s, so a chunk under 20 s is not cut), each part is transcribed on its own, and the parts are put back into one answer of the chunk with times counted from its start. The cache, `chunks_json` and the md writers read that answer as any other; its block `auto_split` says how it was assembled (the parts, their places, the usage of each, how many came back without time marks), and `usage` is the sum of the parts. Before, the client's next request had no `response_format` and the diarize model answered plain text: the whole chunk became one line without time marks and was repaired by an operator split. That old way still applies when the split is off, the chunk is too short, or the parts cannot be cut or transcribed. A part the server refuses three times as well comes back as text and stands at the start of that part. The part files are temporary and are removed after the merge; speaker letters of different parts are independent, as they are between chunks. Checked by tests against a scripted server (`ServerErrorChunkSplitTests`); not yet seen on a live HTTP 500.
- **Plain-text model (`gpt-transcribe`), speech pieces:** a job whose `model` starts with `gpt-transcribe` (set it in the job settings; the shared config keeps the diarize model) goes another way, `SpeechPiecesTranscription`. That model takes several languages and a prompt, so it writes Spanish in Spanish and Russian in Russian inside one phrase — the diarize model takes one `language` and wrote the Spanish of a mostly Russian chunk in Cyrillic — but it answers plain text: no segments, no time marks, no speakers. So every chunk is asked twice: once **whole** (a long stretch gives the best wording) and once in **pieces** cut at its pauses (ffmpeg `silencedetect` inside the chunk file: a pause of `speech_pieces_pause_sec`, default **1.0 s**, ends a piece; a piece that would grow longer than `speech_pieces_max_sec`, default **15 s**, ends at a shorter pause; with silence compression and a kept pause below 1 s that kept pause is the limit; a chunk where the shared `silence_noise_db` finds no pause — steady noise under the voice, a piece would be longer than twice `speech_pieces_max_sec` — is searched again 5 and then 10 dB louder, as long as its pieces keep at least 60 % of the chunk as sound (`SpeechPiecePlanner.PlanAtFittingLevel`; block field `silence_noise_db` names the level used; silence compression keeps the shared level). The whole text is laid onto the pieces word by word without a model (`SpeechPieceWordAlignment`: Needleman–Wunsch over words compared by sound, so «beberse» and «беберсе» are one word), and each piece becomes a line that starts where the piece starts. The answer has the shape of a timed server answer (`text`, `segments`, `usage` = seconds of all requests), so the cache, `chunks_json`, the md writers, the speech map, **retranscribe**, **TranscribeSub** and the merge of an operator split read it as any other; its block `speech_pieces` says how it was assembled (pieces with their own text, words placed by a partner, answers dropped). Requests carry `languages[]` from `speech_pieces_languages` (shared config: `["es","ru"]`) and the prompt `speech_pieces_prompt`; neither is sent to other models, and such a request is never repeated by a fallback model. The request of the whole chunk names the same languages in the order of `speech_pieces_whole_languages` (shared config: `["ru","es"]`; absent or empty = the order of the pieces; a chunk that is one piece is asked as a piece). The order tells: with Spanish first, a long stretch of a lesson held mostly in Russian came back with Russian phrases written in Spanish — translated, the same way in two runs, so comparing runs did not show it; it shows where the line of a piece is Spanish while the same piece asked alone (`own_text`) is Russian and does not sound like it. With Russian first those phrases stay Russian and the Spanish stays Spanish; dropping the prompt changed nothing, and a prompt reworded to forbid translating made the model translate nearly the whole chunk. Measured on the six participant tracks of one lesson (2026-11-14, 1396 lines): such lines 32 → 22 (118 → 52 words in them); of the 22 lines where the line was the wrong one, 13 fixed, 3 partly, 6 left; of 722 pieces that were Spanish both in the line and alone, 720 stayed Spanish; the price of a run did not change. Guards: an answer with more words than can be said in the audio (6 a second + 20 — the model sometimes repeats one word thousands of times), or with one word 20 times in a row (the same loop in a small dose: seen live as «no» 376 times inside an otherwise ordinary text of a chunk, too few words to break the first limit; in 7,300 stored texts of 30 tracks the longest real row is 8), is dropped and asked again, up to three tries; a whole text in which fewer than half of the pieces' words are found is not used, and the pieces' own text stands instead; a piece left without words of the whole text keeps its own. Such a **lone piece** holds what the text of the whole chunk leaves out — a word said twice, a false start, a word thrown in — and a second of sound without its surroundings is where the model most often writes a Spanish word in Cyrillic. A lone piece with Cyrillic letters therefore gets a second look (`SpeechPieceSecondLook`), in two steps. Without a request: when the piece says the first words of the next line or the last words of the previous one and they stand there in Latin letters, it takes that spelling («Томар.» before «tomar agua» becomes «Tomar.»; a word of three sound letters or fewer must sound exactly the same, so «Но.» does not become «nos»). With one short request: otherwise a piece of at least four sound letters is asked again with `speech_pieces_context_sec` seconds of audio on each side (shared config: **5**; `0` switches this step off), and the run of Latin words of that answer whose letters sound most like the piece replaces it when the two are at least 0.6 alike — found by sound, not by place, because that answer drops repetitions too; a run does not go over the end of a sentence, and a piece the answer leaves out or keeps in Russian stays as it was. The piece keeps its own capital letter and end mark. The block `speech_pieces` counts both steps (`pieces_spelled_by_neighbour`, `pieces_asked_with_context`, `pieces_spelled_by_context`) and keeps per piece what it heard alone (`own_text`), the answer with audio around (`context_text`) and which step spelled it (`second_look`: `neighbour` | `context`). Counted on the answers saved from the six participant tracks of one lesson (2026-11-14): of 31 lone pieces in Cyrillic 15 were Spanish and 16 real Russian; the second look respells 9 of the 15 (8 right, 1 doubtful), leaves 6 and changes none of the Russian ones, for about 50 s of extra audio per 40-minute track. The same request settles a **doubted line** of a piece that is not lone: with Russian first the whole text still gives some Russian phrases in Spanish. A line is doubted when its share of Latin words is at least 0.4 higher than that of the piece asked alone and the two sound less than 0.5 alike (the same speech in two spellings, «queremos» and «керемос», is more alike; a piece of fewer than four sound letters doubts nothing), unless the line is word for word a part of what the piece heard (a run of the piece's words at least 0.8 like it: the whole text only left the rest out). Neither is believed as it is — a piece alone mishears too: the piece is asked again with the audio around it, languages in the order of the pieces, and the line is replaced only when that answer has a run of words that holds a Russian word, is at least 0.6 like what the piece heard alone and is more like it than any run of the answer is like the line («Это уже прошлое» in place of «Esto ya es pasado»). The run is taken as it stands, with the piece's capital letter and end mark; a word of it in Cyrillic that the piece alone wrote in Latin letters, sounding exactly the same, keeps the Latin spelling («репартир» becomes «repartir»; not when the piece holds that sound in Cyrillic too). An answer that stands by the line, has neither, or heard Spanish only leaves the line. The **mirror doubt** is rarer and settled by the same request: asked with Russian first, the whole text now and then gives Spanish speech in Russian («Tal vez mañana» as «Может быть, mañana»). A line with a Russian word is doubted when the piece asked alone has a share of Latin words at least 0.4 higher and the two sound less than 0.5 alike — unless one is word for word a part of the other. Here the piece alone is the one that errs more often (it turns a Russian word into Spanish-looking sounds), so the bar is higher: the line is replaced only when the answer with audio around has a run with a Spanish word at least 0.8 like what the piece heard alone, more like it than any run is like the line, and has no Russian word of the line (three letters or more, in Cyrillic) — a word heard there was said, so the line is not a translation. Tried on 30 participant tracks of five lessons (6,795 lines, a paid probe of the doubted pieces): 21 lines doubted, 5 replaced — 4 Spanish phrases the whole text had put into Russian and one «Ага» that became «Ajá. Ajá.»; none of the 16 right Russian lines changed. The block counts both doubts together (`lines_asked_with_context`, `lines_taken_from_context`) and keeps per piece the line that was replaced (`whole_text_line`, with `second_look`: `line`). Run on 14 participant tracks of five lessons (2026-11-14; Russian is from 4 % to 51 % of a track's speech, 3563 pieces): the first build doubted 53 lines and replaced 19, two of them wrongly — a line that was a part of what the piece heard, and a Spanish line replaced by another Spanish run; the part rule and the Russian-word rule above come from those two. Replayed on the stored answers of those runs with both rules: 44 lines doubted, 17 replaced — by reading 15 right, 1 unclear, 1 wrong (Spanish stammering that the piece alone and the answer with audio around both wrote in Cyrillic); the extra audio is 1–3 % of a run. Asked with Russian first, that request wrote English speech in Cyrillic and replaced a right line, so it keeps Spanish first. `speech_pieces_parallel_requests` (default **3**) limits the requests of one chunk running at once. There are no speakers in the answer (every line is `speaker_0`): the way fits a recording of one voice — a participant track, which the orchestrator's dialogue merge names by the participant. Measured on two 40-minute participant tracks of one lesson (2026-11-14): Spanish words written in Cyrillic 84 → 0 and 61 → 0, words in Latin script 247 → 703 and 951 → 1313, 253 and 245 lines (the diarize model gave 316 and 481), line starts within 0.8–1.4 s of the diarize ones in the median, $0.20 and $0.23 per track against $0.44 and $0.51, a track done in 20–60 s. Left as it is: single misheard words differ from run to run, and a Russian word now and then comes out in Latin letters.
- **Sub-chunk timeline:** an operator **Split** cuts a chunk into parts that are transcribed on their own, so the segments of a part count seconds from the start of that part. `split_chunks/chunk_N/sub_chunks_timeline.json` (written by **Split**) keeps where every part starts inside the chunk (`offset_sec`) and how much of it repeats the previous part (`emit_guard_sec`); the merge of the parts (after the last **TranscribeSub** and on **rebuild_split_merged**) reads it. A split made before this file existed is measured from its audio — duration of the chunk and of the first part — and the file is written then with `derived: true`. When the places cannot be established the merge answers `split_merge_sub_offsets_unknown` and writes nothing, instead of stacking all parts at the start of the chunk.
- **Speech map:** with `silence_compress_enabled` the model hears a shorter file — every silence region is replaced by a `silence_keep_sec` gap — and answers in seconds of that file. `timeline/speech_map.json` in the job artifact root lists the kept pieces of the source (`source_start_sec`, `source_end_sec`) and where each stands in the compressed file (`output_start_sec`); the file is assembled from the same plan, so the table is exact. Every writer of transcript lines (first run, **rebuild_combined**, split merge) translates the time of a line back through this table, so `chunks_md/*.md` and the combined transcript carry times of the **recording**; chunk JSON keeps the raw times of the model. A segment that starts in the last 0.35 s of a piece and runs into the next one is placed at the start of the next piece (the model tends to mark a phrase slightly early, and without this the line would land before the whole pause that was cut). A run without compression removes the file. Jobs transcribed before the map existed keep times of the compressed file.
- **`StreamJobStatus` polling:** default **2000 ms** between polls (`Agent04:StreamJobStatusPollMs` in `appsettings.json`) to reduce load; VM updates in Agent04 are immediate; UI sees changes within ~poll interval + network.
- **Chunk cancel (gRPC / UI ×):** while a chunk’s OpenAI request is in flight, the pipeline polls cancel flags and cancels the HTTP call via `CancellationToken` (cooperative abort). Cached chunks skip HTTP and are not affected.
- **HttpClient / «зависшие» запросы:** не пересоздавайте `HttpClient` ради «убить» один зависший вызов — используйте **отмену по токену** и **таймауты** (`HttpClient.Timeout`, дедлайн на токене). Отмена кооперативная: сокет на стороне провайдера может закрыться не мгновенно. Экземпляр клиента из DI держите долгоживущим; `Dispose` — при остановке приложения или смене скоупа, не после каждой ошибки.
- **Logs:** `OpenAITranscriptionClient` emits structured lines for each HTTP call: `AgentJobId`, `ChunkIndex`, `HttpAttemptId`, `ParallelWorkersConfigured`, process-wide **`InFlight`** count, duration, and on failure **HTTP status** with **Category** `auth` (401/403), `rate_limit` (429), `client_error`, `server_error`, `timeout` (**Reason=http_client_timeout** where applicable), plus a truncated response body (no API key / `Authorization`). With **`parallel_transcription_workers` > 1**, log order across chunks is not start order — correlate by **`ChunkIndex`** / **`HttpAttemptId`**.

## Differences from agent01

- **Web service only:** no CLI; start with `dotnet run`; transcription via **gRPC** only.
- **Workspace root:** one required root directory per instance (appsettings/environment); all request paths are relative to it.
- Job status store and progress updates; optional tags; **QueryJobs** on gRPC for filtered lists.
- Output format (Markdown and JSON) is compatible so consumers can use results from either agent.
